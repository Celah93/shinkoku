# 個別の申告データを扱うとき

一般的な制度説明やコード・Skillの編集には、納税者の設定・DB・進捗を読みません。個別の試算、帳簿処理、入力代行で必要になったときだけ使います。

- 対象年度、必要な入力、DB・出力先を既存設定や依頼から確認します。`shinkoku.config.yaml` の相対パスはCWD基準で解決し、DB操作には同じ絶対パスを渡します。設定がなくても一般説明や提供データによる試算を進め、不足する保存先等が必要な操作だけ保留します。
- 継続時は `.shinkoku/progress/progress-summary.md` から対象工程を見つけ、必要な引継書だけを読みます。全工程を読み直しません。現在のDB値・原本と食い違えば原因を確認し、古い進捗で確定値を上書きしません。
- 既知・確認済みの事実を聞き直しません。未知の家族構成、控除適用、予定納税、課税区分等を「なし」や0と仮定して申告額を確定しません。不足情報をまとめて確認し、無関係な作業は続けます。
- 先行Skillの実行履歴ではなく必要なデータが揃っているかで開始を判断します。事業所得がなければ決算書作成を前提にせず、対象外の所得や未対応機能は対応済みと扱いません。対応範囲は [capabilities](../capabilities/SKILL.md) を必要時に確認します。
- 実帳簿への登録・修正・削除、既存設定の上書き、申告方法の確定は、具体的な差分や一覧を示しユーザー確認を得てから行います。確定済みの同一内容には再承認を求めません。読取・試算・使い捨てデータでの検証は依頼範囲で続けます。
- 本人認証、マイナンバー入力、署名、最終送信は本人操作です。認証や送信の完了をユーザーが報告するまではブラウザ操作を止めます。最終確認・送信意思の確認は計算途中の確認と区別します。
- 個人情報を含む原本・設定・DB/WAL/SHM・`.data`・進捗・出力は非公開のまま保持し、公開文書・Git履歴・不要なログに混ぜません。原本や既存DBの初期化・削除をしません。
- 金額は円単位の整数とし、資料の対象年度と端数処理を守ります。別年度や未確認の制度を記憶で補わず、必要な公式根拠を確認します。
- サブエージェントはユーザーがこの会話で明示的に依頼した場合だけです。該当Skillを読むことと別エージェントを起動することを区別します。

指定された工程の出力を作り、CLI結果・集計・入力との照合で問題を直して再確認します。永続データを更新したら読戻しで確認し、実行・承認・提出の状態を区別して記録します。進捗の形式が必要な場合だけ各Skillの結果記録の参照を使い、未完了を `completed` にしません。
