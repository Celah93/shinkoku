# 計算ごとの対応年分

所得税計算・控除集計・ふるさと納税の上限推定・高所得特例は2025〜2027年分を対象とする。消費税は方式別に年分を検証する。対象外の年分を旧制度で計算しない。

## 計算と保存の範囲

| 機能 | 年分の扱い |
|---|---|
| `tax calc-income` | 2025〜2027年分。所得税と追加税を含む計算全体を対象とする |
| `tax calc-deductions` | 2025〜2027年分。年分別の控除集計を対象とする。省略時の2025年という既存入力契約は維持 |
| `tax calc-consumption` | 本則・簡易・2割特例は2025・2026年分。3割特例は国内個人の2027・2028年分。未対応年分・申告用の未確認要件等はDB照合前に止める |
| `tax calc-furusato-limit` | 2025〜2027年の寄附。2027年は住民税に基づく入力が必要。旧年度・旧入力の省略年分2025と単一値JSONは維持 |
| `tax calc-furusato-limit-detailed` | 2025〜2027年。住民税資料から推定し、寄附額の上限と特例控除上限・住民税年度・税率判定を別々に返す |
| `tax calc-resident-tax-estimate` | 2025〜2027年所得。確認済みの総合課税所得・課税区分・控除元データから標準所得割を推定し、既存上限計算の入力も返す |
| `tax calc-housing-loan` | 2022〜2030年入居の住宅ローン単体計算。控除年と入居年を区別する。2025年以前入居の小規模床面積特例は対象外。年間所得税の許可年分は変更しない |
| `tax calc-minimum-income` | 2025〜2027年。高所得特例の二段階判定と加算計算。再計算待ちは最終額を返さない。株式・退職等の通常税額は入力側で計算済みであることが必要 |
| `tax sanity-check` | 入力と保存済み結果の両年分を検証。未対応年分や年分の不一致はエラー |
| 帳簿・寄附等の保存 | 将来年の記録を保持できる。記録の存在は申告計算への対応を意味しない |
| 年度別の消費税方式の保存 | 3割特例は2027・2028年分だけに保存できる。既存方式の過去・将来年の記録は保持するが、税額計算には上記の方式別年分制限を適用する |
| `tax calc-pension` | 2025〜2027年分。2027年の正の年金収入には給与所得控除額（給与なしなら0）を明示する。年間計算の `pension_income` からも呼び出す |
| 個別の税制定数・単体計算 | 実装済みの2027年分の基礎控除等や、将来の仕入控除割合は保持。退職所得等の単体計算を含め、これらの存在から申告全体の対応を判断しない |

年間計算等の許可年分は [`tax_year_support.py`](../src/shinkoku/tax_year_support.py)、住宅ローンの入居年は `tax_constants.py` の年別ルールを正本とする。対象者や申告方法の適格性、個別例外、様式、実サイトとの一致がすべて検証済みという意味ではない。

3割特例の相続の例外は登録日・相続日を比較する。国税と地方税の中間納付も別々に精算する。2027年の所得税の変更点は[2027年分の計算](income-tax-2027.md)、ふるさと納税と高所得特例の入力・残る対象外範囲は[専用資料](furusato-and-minimum-tax-2027.md)を参照する。国税庁画面への入力は未検証。青色控除・2割・3割特例の確認済み事実と試算・申告用の区別は[適用判定](tax-eligibility.md)を参照する。

## ふるさと納税の入力例

新しい入力では、対象の寄附年を明示する。

```json
{
  "fiscal_year": 2026,
  "total_income": 5000000,
  "total_income_deductions": 1500000
}
```

上は2025・2026年用の旧形式の概算。2027年は住民税所得割・課税所得・人的控除差・所得税基礎控除を入力する。計算済みの住民税資料を使うほか、[住民税控除の自動組立て](resident-tax-estimate.md)の結果を渡せる。詳しい入力例は[専用資料](furusato-and-minimum-tax-2027.md)を参照する。

## 未対応と表示された場合

対象年を対応済みの年へ変えたり、`fiscal_year` を削除して省略時の年分へ流したりして再計算しない。必要な制度の対応を待つか、その年分に対応した計算・申告手段へ案内する。エラーは既存の `status`・`message` を持つJSONと終了コード1で返し、税額や検算成功を返さない。

## 次の年分を有効にする条件

対象機能の制度一式、適用要件、年分境界、入出力、CLI、必要なDB保存、Skillの案内をそろえ、既存年分の回帰テストと新年分の検証を通してから、その機能の許可年分を追加する。定数の一部が前年と同じことだけを理由に有効化しない。
