# 2027年のふるさと納税上限と高所得特例

2027年のふるさと納税は、住民税の資料から上限を推定できる。高所得者向けの「特定の基準所得金額の課税の特例」は、専用CLIで二段階の判定・加算税額を計算し、対応する所得だけを持つ人は年間所得税計算にも反映する。いずれも公式画面への入力・提出確認とは別の対応である。

## ふるさと納税の193万円上限

193万円は**寄附額ではなく、住民税の特例控除額の合計上限**。寄附した2027年に対し、2028年度の住民税へ適用する。2025・2026年の寄附には定額上限を適用しない。

| 住民税の区分 | 都道府県民税 | 市町村民税 | 合計 |
|---|---:|---:|---:|
| 一般の市町村 | 772,000円 | 1,158,000円 | 1,930,000円 |
| 指定都市 | 386,000円 | 1,544,000円 | 1,930,000円 |

今回の推定は標準税率で計算した合算所得割額を使う。自治体ごとの超過税率、各税額の端数や他の税額控除まで確定する住民税計算ではない。ふるさと納税以外の寄附、住宅ローン控除、高所得特例、分離課税などがある場合や寄附によって所得税率の区分が変わる場合、自己負担2,000円を保証しない。

### 入力

```bash
shinkoku tax calc-furusato-limit-detailed --input furusato_limit.json
```

```json
{
  "fiscal_year": 2027,
  "resident_tax_income_levy": 10000000,
  "resident_taxable_income": 100000000,
  "personal_deduction_difference": 0,
  "income_tax_basic_deduction": 0
}
```

上は架空データ。`resident_tax_income_levy` は標準税率による住民税所得割額の合計で、調整控除後・寄附金や住宅ローン等の他の税額控除前。`resident_taxable_income` は住民税の課税総所得金額。所得税の課税所得や、そのままの給与収入で代用しない。

`personal_deduction_difference` は住民税の調整控除計算に使う人的控除差で、所得税・住民税の控除合計を単純に引いた額ではない。`income_tax_basic_deduction` は寄附年の所得税の基礎控除額。住民税の課税年度から見れば前年分の所得税である。

適用する限界税率が確認済みなら、整数の `income_tax_rate_percent`（0・5・10・20・23・33・40・45）を指定できる。未確認の税率を都合よく選ばない。省略時は次の式から判定する。

1. 税率判定用の調整額 = 人的控除差 + max(0, 所得税基礎控除額 − 480,000円)
2. 税率判定用所得 = max(0, 住民税課税所得 − 調整額)
3. 特例控除上限 = min(住民税所得割額 × 20%, 1,930,000円)
4. 寄附上限の推定 = 特例控除上限 ÷ (90% − 限界税率 × 1.021) + 2,000円

税率は途中で切り捨てず、整数の分子・分母で計算する。住民税所得割額が0円なら推定上限も0円。基本分や所得税側の別の限度額まで満たすかは、この特例控除枠の推定とは別に確認する。

結果には `estimated_limit`（寄附額）、`special_credit_limit`（特例控除額）、`fixed_cap_applied`（定額上限による制限の有無）、`resident_tax_assessment_year`（住民税年度）、調整額・税率・端数処理用の分子と分母を返す。上限の直前・一致・直後もテストしている。

既存の `tax calc-furusato-limit` に同じ入力を渡すと、従来どおり `{"estimated_limit": 金額}` だけを返す。2025・2026年は `total_income` と `total_income_deductions` を使う旧形式の概算を維持する。2027年は上記の住民税項目を必須とし、旧形式へ自動的に戻さない。2028年以後は未対応のため停止する。

## 高所得者向け特例の年分と計算

| 所得の年分 | 基準所得から引く額 | 比較に使う率 |
|---|---:|---:|
| 2025・2026年 | 330,000,000円 | 22.5% |
| 2027年 | 165,000,000円 | 30% |

基準を超えた人全員に税額が増えるわけではない。通常の税額と比較して判定する。

### 専用CLI

```bash
shinkoku tax calc-minimum-income --input minimum_income.json
```

```json
{
  "fiscal_year": 2027,
  "calculation_mode": "filing",
  "income_scope_confirmed": true,
  "incomes": {
    "comprehensive_income": 500000000
  },
  "ordinary_income_tax": 40000000,
  "uses_nonfiling_system": false
}
```

この入力例は計算式を示すための架空データであり、収入から通常の所得税4,000万円が自動算出されるという意味ではない。通常税額は、特例適用前の申告計算から別途得る。

`incomes` は国税庁計算書①〜⑫に相当する、計算済みの所得金額。繰越損失・土地等の特別控除を引いた後、申告不要制度は使わずに集計する。NISA等の非課税所得や預金利子等の源泉分離課税所得は含めない。重複計上しない。

| フィールド | 対象となる計算済み所得 |
|---|---|
| `comprehensive_income` | 総合課税の所得の計 |
| `short_term_capital_general` / `short_term_capital_reduced` | 分離短期譲渡の一般分・軽減分 |
| `long_term_capital_general` / `long_term_capital_specific` / `long_term_capital_reduced` | 分離長期譲渡の一般分・特定分・軽課分 |
| `general_stock_gains` / `listed_stock_gains` | 一般株式・上場株式の譲渡所得等 |
| `listed_stock_dividends` | 分離課税の上場株式等の配当等 |
| `futures_income` | 先物取引に係る雑所得等 |
| `forestry_income` / `retirement_income` | 山林所得・退職所得 |

総合課税以外の各項目は省略時0だが、申告用の `income_scope_confirmed: true` は、申告不要にする予定の所得も含めて全項目を確認した場合だけ指定する。株式・退職等の**通常税額をこのCLIが収入から算出するわけではない**。その計算や申告書第三表の作成は既存の対象外範囲に残る。新しい分離課税制度の施行・対象判断を、その他の所得へ無断で振り替えない。

`ordinary_income_tax` は特例による加算と復興・防衛税を加える前、国内の税額控除を反映した通常の所得税額。源泉徴収・予定納税を引く前であり、外国税額控除・分配時調整外国税額控除の適用前を使う。復興・防衛税は年分から自動計算する。

### 二段階の判定

1. 全所得の合計から年分別の基準額を引き、**その差額を1,000円単位で切り捨ててから**22.5%又は30%を掛ける。これが `benchmark_tax`。
2. 通常の所得税・追加税に、申告不要予定所得の源泉税を足した `initial_base_tax` と比較する。差額が0以下なら特例なし。
3. 申告不要予定の所得がある場合は `uses_nonfiling_system: true` と、その所得に係る国税の源泉徴収税額（追加税込み、住民税は除く）を `nonfiling_income_withheld_tax` に渡す。初回判定で差額が正なら、申告不要制度を使わず、人的控除等の所得制限も再判定して通常の所得税を計算し直す。
4. 再計算値を `recalculated_income_tax` に渡す。入力がなければ `status: "requires_recalculation"` とし、加算額・最終税額は `null`。終了コード0をもって最終計算完了と扱わない。
5. 再計算した所得税と追加税の合計が `benchmark_tax` 未満なら、その差を `additional_income_tax` として所得税へ加算する。**加算後の所得税も復興・防衛税の課税標準になる**。1.021で割り戻さない。

再計算により差額が0以下になる場合も特例なし。その場合、申告不要制度を強制的に解除した値を最終結果として採用せず、当初の通常計算を保持する。結果は `not_applicable`、`requires_recalculation`、`applicable` のいずれかになる。

上の2027年の算式例では、比較額100,500,000円、通常所得税・追加税40,840,000円、加算所得税59,660,000円。加算後の所得税99,660,000円に復興税1,096,260円・防衛税996,600円を足し、合計101,752,860円となる。この `total_tax` は源泉・予定納税の精算前。

### 年間計算への反映

`tax calc-income` の対応する所得だけで全所得がそろう場合、基準所得を繰越控除後の `total_income` から計算し、特例を自動的に比較・加算する。基準超の申告用計算では `minimum_tax_income_complete: true` が必須。未確認の試算には、入力済み所得だけで計算している警告を返す。`false` は所得不足を意味するため、試算でも停止する。

結果の `income_tax_after_credits` は特例加算前、`minimum_tax_additional_income_tax` が加算額、`income_tax_after_minimum_tax` が加算後。追加税の基準には最後の値を使う。`minimum_tax_detail` に途中計算を残し、申告用検算で主要金額と内訳を再計算する。寄附の所得控除・税額控除を比較する際も、この特例を含む合計税額を使う。

計算対象外の株式・退職等がある場合は、専用CLIの判定・加算計算と、通常税額・申告書全体の作成を分ける。申告書の特例適用条文や計算書添付も必要となるため、最新の公式手引きに沿って確認する。2027年の公式様式・画面との照合は未検証で、過年度の欄番号を転用しない。

## 根拠と検証

2026-09-13に確認した一次資料。画像5枚はGeminiにも読ませ、原資料の本文・欄と照合した。返答中の一部の第一表欄番号は画像に合わせて補正し、税額と算式を採用した。

- [財務省・地方税法等の改正931〜932頁](https://www.mof.go.jp/tax_policy/tax_reform/outline/fy2026/explanation/PDF/p0921-0989.pdf): 控除上限193万円、2028年度からの適用、基礎控除増額を含む税率調整。
- [財務省・所得税関係の改正422〜425頁](https://www.mof.go.jp/tax_policy/tax_reform/outline/fy2026/explanation/PDF/p0210-0436.pdf): 高所得特例の基準・対象所得・2027年からの30%。
- [国税庁No.2270](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/2270.htm): 基準所得の集計範囲と繰越控除、通常税額の意味、申告不要制度・人的控除の再判定。掲載された3.3億円・22.5%は2025・2026年用であり、2027年の数値は上の財務省資料で確認。
- [国税庁・適用判定表兼税額計算書](https://www.nta.go.jp/taxes/tetsuzuki/shinsei/annai/shinkoku/annai/gengaku/01.pdf)と[記載例](https://www.nta.go.jp/taxes/shiraberu/shinkoku/kisairei/pdf/tokutei.pdf): 千円単位の丸め、二段階判定、加算後の復興税。記載例の最終税額162,710,519円と納付1,903,000円を回帰テストで再現。

年分・上限の直前/一致/直後、再計算待ち、再計算後の非該当、必要情報の欠落、通常計算との合算、架空の帳簿からCLI・検算までをテストする。実ユーザーの帳簿や申告画面は検証に使っていない。
